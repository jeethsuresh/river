# Android message notifications

River receives background alerts through Private Store's `appstore/1.0.0` protocol. Install the signed River release, sign in to River and Private Store with the same Gravitas account, enable **App notifications** in Private Store, then enable **Settings → Message notifications** in River and approve Android's notification permission. Open Private Store after updating so it refreshes its supporting-app catalog. Private Store's optional **Allow screen-off notifications** setting controls delivery during Doze.

Gravitas applies Matrix push rules to both local and federated events. It queues an alert in the event's database transaction, then rechecks read receipts, membership, ignored users, account state and River/Store grants before handing it to the protocol relay. Muted events do not create alerts. Committed database notifications wake both workers promptly; lease recovery and bounded backoff handle failures. Pending payloads expire after seven days.

The relay sends one `push.broadcast` invocation per recipient/event. Private Store owns installed devices, certificate checks, durable replay and acknowledgements. River acknowledges authenticated Store provider reconciliation without maintaining a second device registry. The protocol receipt confirms durable acceptance, not Android display.

Native payload fields are `kind: "matrix.event"`, `issuer`, `subject`, `room_id`, `event_id` and a positive monotonic `sequence`. They contain no message body, sender, room title, ciphertext or access token. The native receiver checks the actual Binder UID and Private Store's permanent signing certificate. It binds the cached subject to River's encrypted saved-session fingerprint, respects notification permission/channel and per-account opt-in, and suppresses replay or older alerts. Sign-out clears displayed alerts and the binding. Tapping an alert opens only a joined or invited conversation belonging to the current account. After rendering a generic alert immediately, River schedules an Android background job to fetch the event and decrypt it with the saved Matrix device. The same notification is updated quietly with the conversation name, sender and a plain-text preview. Private Store and River’s relay never receive the preview.

The Binder receiver returns promptly. `NotificationPreviewService` uses JobScheduler with a network requirement and expedited execution on Android 12 or later, falling back to an ordinary job when expedited quota is unavailable. A cold job lazily starts a headless Flutter engine, restores only the encrypted identity and Matrix session, and performs bounded event fetch/key synchronization through the production SDK. It does not launch authentication or load the workspace. Opening River promotes that same engine to the UI; app and bubble windows continue sharing one Matrix device and durable refresh-token owner. Android may defer jobs under background restrictions. Offline, locked storage, missing keys and expired sessions leave a generic alert. Invitations and non-message events retain generic alerts. These notifications support Android; the Store protocol does not provide desktop or browser push delivery.

Decrypted content is handed only to Android’s local notification UI, with private visibility and a generic public lock-screen version. River does not write previews to its push preferences or send them back to the relay; Android manages notification history according to the device’s settings. Bubble shortcut labels show the conversation name after decryption. Pending work stores only bounded identifiers, session fingerprints and ordering metadata. A preview cannot replace a newer event, revive a read/dismissed alert, or cross a sign-out/account/session change; work older than five minutes cannot update an alert. Plain text is bounded, remote HTML is ignored, and attachments use labels such as Photo or File. A key unavailable during the bounded attempt leaves the generic alert until a later message or normal conversation open.

## Conversation bubbles

On Android 11 or later, message notifications offer Android's bubble control. Enable message notifications first, then choose **Settings → Conversation bubbles** in River to select Android's app-wide bubble preference, or use the bubble button on a conversation notification. Android and the user's per-conversation choice decide whether an alert floats; River does not auto-expand bubbles. Earlier Android versions retain ordinary notifications.

Each alert publishes an account-specific, long-lived conversation shortcut with `Person` and `MessagingStyle` metadata. The label and message begin generic; local decryption updates the conversation label and message preview. History is available through River's authenticated conversation view when the bubble opens. Opening uses the same account and membership validation as a normal notification tap.

Resizable bubble documents and the fullscreen window reuse one lazily created Flutter engine and Matrix device. When a new document takes the engine, the previous document keeps its Android task and recreates its detached Flutter view when shown again; the running app state and drafts remain in Dart. Read receipts dismiss ordinary alerts while preserving active bubbles. Signing out removes bubbles and conversation shortcuts. The Android emulator checks metadata, distinct conversation identities, read behavior, and switching real Flutter hosts alongside the notification tests.

## Hosted configuration

Configure one distinct random credential of at least 32 characters in:

- River Secret `river/river-notifications`, key `provider-key` (`NOTIFICATION_PROVIDER_KEY`).
- Private Store's `appstore-notifications/app-keys`, adding `river=THE_CREDENTIAL` while preserving existing apps.
- IAM's `PROTOCOL_SERVICES`, adding `https://chat.gravitas.cool` with that key and `protocols.read`, `appstore.push`, `appstore.push.broadcast` permissions.

IAM's hosted overlay sets `MATRIX_APPSTORE_PUSH_ORIGIN=https://chat.gravitas.cool`. Independent homeservers leave it unset to disable this integration. Private Store's catalog pins River's package, permanent certificate, notification authority and backend origin. No user-supplied callback URL is accepted.

Run Flutter analysis/tests and Go race tests/vet. The Android CI emulator runs `StoreNotificationDeliveryTest` against the real OS notification manager, covering native display, decrypted Unicode previews, private lock-screen content, stale/read/sign-out guards, replay/order, account/session changes, explicit disable, denied notification permission and unsigned Binder calls. Flutter tests cover headless restoration, foreground handoff and credential persistence after errors. The isolated Matrix SDK interoperability fixture verifies fetching and decrypting an encrypted event before the recipient has synced its to-device key, plus redaction and self-message suppression. IAM's Matrix/Store integration test checks the real encrypted-event outbox, protocol relay, Store stream and acknowledgement.
